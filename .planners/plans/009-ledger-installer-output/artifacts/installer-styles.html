What breaks on macOS

  • Bold yellow Warning: renders as bright yellow when Terminal brightens bold text: 1.3:1 on the Basic white background. The one line a Mac user must act on (~/.local/bin is not on PATH by default) is the hardest to read.
  • Color is never gated. Piped to a file or a CI log, every line carries raw escape codes. Try Piped.

Also

  • The PATH hint names ~/.bashrc, ~/.zshrc, etc. rather than the user's shell. On a Mac that is zsh, and login bash reads ~/.bash_profile, not ~/.bashrc.
  • 49 lines for a successful install; each step prints a start line and a done line.

B. Ledger

recommended

The idea

  • The installer speaks the same row grammar as stanza release: a stanza install header, then dim 8-column labels (LABEL_WIDTH) with the content beside them.
  • Color sits on the label only (warn, hint, error, done). The label word carries the meaning, so a weak hue costs nothing.

Trade-offs

  • One voice: first contact looks like the tool you just installed.
  • Short run: 16 lines for the same install, against 49 today.
  • Duplicated helper: curl | bash cannot source lib/stanza-common before the download, so install.sh carries its own 20-line copy of print_row and the color gate.

Standard ways to do this in bash

There is no styling library that ships with macOS. Installers meant for curl | bash almost all hand-roll it: a few printf escape codes behind a terminal check. A package would be one more thing to download before the download.

Keeping it safe on macOS

macOS runs install.sh under /bin/bash 3.2 with BSD tools, in Terminal or iTerm2 with the user's own color theme. Each rule below is cheap to follow and shows up in one of the mockups.

red 315.5:13.8:1
green 322.5:18.3:1
yellow 332.4:18.8:1
bright yellow1.3:116.5:1
blue 347.6:12.8:1
magenta 354.0:15.3:1
cyan 362.3:19.1:1

Contrast of Terminal's ANSI colors on the Basic (white) and Pro (black) backgrounds. No hue reads well on both, which is why the mockups let the word carry the meaning and use color as a second cue.

Use the 16 basic colors only

SGR 30–37 plus bold. They follow the user's theme (Solarized, Dracula, and so on). Avoid 256-color and 24-bit codes, which ignore the theme and which older Terminal versions do not render.

Never rely on bold yellow

With "Use bright colors for bold text" on, bold yellow becomes bright yellow on white. Put meaning in the word (warn, Warning) and keep the hue on the label only.

Gate on the fd you write to

curl | bash pipes stdin, not stdout, so [ -t 1 ] still sees the terminal. Check -t 2 for stderr lines. Also honor NO_COLOR, TERM=dumb, and CLICOLOR_FORCE.

Glyphs only in a UTF-8 locale

Test LC_ALL, then LC_CTYPE, then LANG for UTF-8, and fall back to ASCII. Today's ━ rules print unconditionally.

Write bash 3.2

No declare -A, ${x,,}, mapfile, &>>, |&, ${a[-1]}, or printf '%(…)T'. Under set -u, "${arr[@]}" on an empty array is an error in 3.2.

No cursor tricks or width probes

Skip spinners, \r redraws, and tput cols. They garble logs and $COLUMNS is not exported to scripts. Keep lines under about 76 columns and rules at a fixed width.

Name the right startup file

macOS defaults to zsh (~/.zshrc). Login bash on macOS reads ~/.bash_profile; on Linux, ~/.bashrc. Pick from ${SHELL##*/} and uname -s, and print one exact line.

Use printf, not echo -e

printf '%b' behaves the same everywhere. echo -e and echo -n differ between bash, sh, and zsh's builtin.

The whole helper, bash 3.2 safe

# Color only for a terminal, and only when nobody opted out (no-color.org).
# CLICOLOR_FORCE asks for color even in a pipe (BSD/macOS convention).
_use_color() {
    [ -n "${NO_COLOR:-}" ] && return 1
    [ -n "${CLICOLOR_FORCE:-}" ] && [ "$CLICOLOR_FORCE" != 0 ] && return 0
    [ "${TERM:-dumb}" = dumb ] && return 1
    [ -t "${1:-1}" ]
}

# Glyphs only in a UTF-8 locale
case "${LC_ALL:-${LC_CTYPE:-${LANG:-}}}" in
    *[Uu][Tt][Ff]-8* | *[Uu][Tt][Ff]8*) GLYPH_OK='✓' GLYPH_BAD='✗' ;;
    *) GLYPH_OK='+' GLYPH_BAD='x' ;;
esac

# "  label   content", label colored when fd $3 (default 1) is a terminal
row() {
    local label="$1" content="$2" fd="${3:-1}" code="${4:-2}" on="" off=""
    if _use_color "$fd"; then on=$(printf '\033[%sm' "$code"); off=$(printf '\033[0m'); fi
    printf '  %s%-8s%s%s\n' "$on" "$label" "$off" "$content" >&"$fd"
}
tilde() {
    case "$1" in
        "$HOME"/*) printf '~%s' "${1#"$HOME"}" ;;
        *) printf '%s' "$1" ;;
    esac
}
